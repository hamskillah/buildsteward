# Project discovery and constraints

**When**: new product, large feature, ambiguous request.

1. Identify the user, problem, expected outcome, target platform, budget, runtime, deadlines and non-goals.
2. Inspect the repository and deployment reality before selecting architecture.
3. Separate facts, user choices, assumptions, and hypotheses. Prioritize only missing details that change irreversible decisions.
4. Ask a strategic grill question with a recommended default *only* if a material decision cannot be responsibly made.
5. Derive acceptance criteria and a vertical slice. Do not turn speculative features into requirements.
6. In approval mode propose decisions with recommendations and a scoped approval request.

**Exit**: enough clarity to build a working, verifiable first slice. When blocked, work on independent tasks.
